How Meridian works

Meridian finds every call to an API that's being retired, who owns it, how risky it is and which teams are stuck waiting on each other. Rules decide the facts; LLM agents only write them up, and a fact gate checks every word. The tools cut the noise so a model reads only what matters, and when a tool comes back empty, the graph walkers go straight to the code graph.

Guardrails

  • Code decides, models write. Facts come from rules over the block. An LLM never decides a fact.
  • Every plan ends. One planning call, a closed menu, each step once. A bad answer gets the rules plan.
  • Code decides when a tool failed: an error, a hang, nothing usable, or two gate misses. Then the walkers run.
  • Walkers are boxed in: read-only, named queries only, 3 teams, 2 hops, 24 queries per stall.
  • No people in facts. A fact with an email is refused before a prompt is built.
  • Every answer is cached by model, prompt version and facts, so reruns cost nothing and match byte for byte.
